# Phase 1 Target Detail — Go

Detailed targeting modes, path validation, preflight checks, Go naming conventions, and shared test helpers for the Go generate spoke.

## Path Validation (Full Detail)

Before processing any target path through the targeting modes, validate the path to prevent filesystem traversal attacks, canonicalization issues, and invalid inputs. Apply these six validation steps, **in this exact order**, to every user-supplied path — ordering matters for security:

```
1. Traversal rejection: Reject raw userPath containing ".." or starting with "/".
   if strings.Contains(userPath, "..") || strings.HasPrefix(userPath, "/"):
     fmt.Println("Invalid path: directory traversal detected.")
     Exit.

2. Canonicalize: Resolve symlinks and relative segments (./) using filepath.EvalSymlinks() + filepath.Clean().
   canonical, err := filepath.EvalSymlinks(filepath.Clean(userPath))

3. Boundary check: Verify the canonical path is within the project root.
   if !strings.HasPrefix(canonical, projectRoot):
     fmt.Printf("Path escapes project boundary: %s\n", userPath)
     Exit.

4. Existence check: Verify the file or directory exists.
   if _, err := os.Stat(canonical); os.IsNotExist(err):
     fmt.Printf("Path does not exist: %s\n", userPath)
     Exit.

5. File type check: If targeting a single file, verify it matches *.go.
   if isFile && !strings.HasSuffix(canonical, ".go"):
     fmt.Printf("File type not supported: %s. Expected .go.\n", canonical)
     Exit.

6. Sensitive file exclusion: Reject files matching sensitive filename patterns.
   Sensitive patterns (case-insensitive): .env, .env.*, *.pem, *.key, *.p12, *.pfx, *.jks,
     id_rsa*, id_ed25519*, id_ecdsa*, credentials.*, service-account*.json,
     .netrc, .npmrc, .pypirc, .aws/*, .ssh/*, .gnupg/*, *.keystore, *.truststore
   basename := filepath.Base(canonical)
   if matchSensitive(basename):
     fmt.Printf("Sensitive file rejected: %s. Test generation for credential and key files is blocked for security.\n", canonical)
     Exit.
```

All six checks must pass before the path enters any targeting mode. If any check fails, print the error and exit — do not fall through to other modes.

## Targeting Modes (Full Detail)

#### Mode 1: Explicit path argument

```
If a <path> argument is provided:
  Resolve the path relative to the project root.
  If path is a file:
    Validate it matches paths.src glob pattern.
    If it's a test file (*_test.go): error, "Cannot generate tests for a test file."
    If it has // Code generated by header: error, "Cannot generate tests for generated code."
    Set targets = [path]
  If path is a directory:
    Glob all files matching paths.src within the directory.
    Filter out files already covered by existing tests (from testInventory).
    Set targets = matched files.
  Skip all other targeting modes.
```

#### Mode 2: `--untested` flag

```
If --untested flag is set:
  If mode is "scan-guided":
    Filter gaps[] where hasTest == false.
    Set targets = gaps[].sourcePath sorted by priority (critical first).
  If mode is "filesystem-scan":
    Glob all files matching paths.src (**/*.go excluding *_test.go and vendor/).
    For each source file, check if corresponding test file exists by naming convention:
      calc/discount.go → calc/discount_test.go
    Set targets = source files with no corresponding test file.
```

#### Mode 3: `--type <kind>` flag

```
If --type <kind> is specified (kind = handler | service | repository | utility | model | middleware):
  If mode is "scan-guided":
    Filter gaps[] by the type of test that would be generated.
    Handler: files importing net/http, gin, echo, or containing http.HandlerFunc
    Service: files with struct types containing business logic methods
    Repository: files importing database/sql or containing data access patterns
    Utility: files with only pure functions (no struct methods, no side effects)
    Model: files with data structs, JSON tags, validation methods
    Middleware: files with http.Handler or framework middleware signatures
  Else:
    Glob files matching paths.src and classify by type heuristics.
  Set targets = filtered files sorted by priority.
```

#### Mode 4: `--critical` flag

```
If --critical flag is set:
  Prioritize entry points, authentication modules, data handling, payment logic, error-prone modules.
  If mode is "scan-guided":
    Filter gaps[] where priority is "critical".
    If no critical gaps: expand to "high" priority.
  Else:
    Identify critical files by heuristics:
      - Files imported by 5+ other packages (high impact radius)
      - Files matching patterns: auth*, login*, payment*, checkout*, permission*, middleware*, handler*
      - Entry points: main.go, cmd/*/main.go
      - Files with high cyclomatic complexity (many switch/case, if/else branches)
      - Packages with exported error types or custom error handling
  Set targets = prioritized files.
```

### Default (no flags)

```
If no targeting flag is provided and no path argument:
  If mode is "scan-guided":
    Set targets = gaps[] sorted by priority (critical → high → medium), limited to top 10 files.
  Else:
    Print: "No target specified. Use one of:"
    Print: "  /bestest generate <path>        — Generate for a specific file or directory"
    Print: "  /bestest generate --untested     — Generate for all files with no tests"
    Print: "  /bestest generate --type <kind>  — Generate for a specific code type"
    Print: "  /bestest generate --critical     — Generate for critical-priority gaps"
    Exit.
```

## Go Test File Naming Conventions

Generated test files follow Go's strict naming convention. Test files must end in `_test.go` and be placed in the same directory as the source file (for white-box testing) or a separate test package directory.

| Source File | Generated Test File | Package |
|-------------|-------------------|---------|
| `calc/discount.go` | `calc/discount_test.go` | `package calc` (white-box) |
| `handlers/users.go` | `handlers/users_test.go` | `package handlers` (white-box) |
| `service/user.go` | `service/user_test.go` | `package service` (white-box) |

Detect existing convention by scanning existing `*_test.go` files. If existing tests use `package xxx_test` (black-box), match that convention. Default to white-box (`package xxx`) for maximum access to unexported symbols.

**Package declaration rule:**
- White-box: `package calc` (same as source) — can access unexported symbols
- Black-box: `package calc_test` (suffix `_test`) — only exported symbols visible

## Go Environment Checks (Full Detail)

```
Check for Go toolchain:
  1. Run: go version
     Verify Go 1.18+ is installed (fuzz testing requires 1.18+; table-driven tests work on all versions).
  2. Run: go env GOROOT GOPATH
     Verify Go environment is configured.

If Go is not installed:
  Print: "Error: Go toolchain not found. bestest requires Go 1.18+."
  Print: "Install Go: https://go.dev/dl/"
  Print: "  macOS: brew install go"
  Print: "  Linux: snap install go --classic or download from https://go.dev/dl/"
  Exit.

Check for go.mod:
  1. Check for go.mod in project root → Go module project.
  2. Extract module path from `module` directive.
  3. Extract Go version from `go` directive.

If no go.mod found:
  Print: "Error: No go.mod found. bestest requires a Go module."
  Print: "Initialize a module: go mod init <module-path>"
  Exit.

Check for testify in go.mod:
  Run: grep "github.com/stretchr/testify" go.mod
  If testify is a dependency:
    Extract which testify packages are used:
      grep -r "github.com/stretchr/testify" --include="*_test.go" | grep -oP 'testify/\K(assert|require|mock|suite)'
    Record which packages are active (assert, require, mock, suite).
  If testify is NOT in go.mod:
    Print: "Warning: testify is not in go.mod. testify provides superior assertion diagnostics."
    Print: "Install: go get github.com/stretchr/testify"
    Print: "Generation will use standard library testing.T assertions as fallback."
    Set testify.enabled = false
    Continue in degraded mode (tests use t.Errorf/t.Fatalf instead of assert.Equal).

Check for go test -json support:
  Run: go help testflag 2>&1 | grep -q json
  If -json is supported:
    Set json_output = true
  Else:
    Set json_output = false (older Go versions; parse plain text output)
```

### StackProfile Framework Detection Heuristics

```
Detection heuristics (in priority order):
  1. Check go.mod for github.com/gin-gonic/gin → Gin framework
  2. Check go.mod for github.com/labstack/echo → Echo framework
  3. Check go.mod for github.com/go-chi/chi → Chi router
  4. Check go.mod for google.golang.org/grpc → gRPC services
  5. Check go.mod for database/sql + driver → Database operations
  6. Check source imports for net/http patterns → stdlib HTTP handlers
  7. If none detected → plain Go testing

If framework cannot be detected:
  Print: "Cannot determine web framework. Generating standard Go tests."
  Set framework = "generic"
```

### Schema Version Validation Algorithm

```
Validate stack-profile.json schemaVersion (if loaded):
  Expected version: ≤ 1.3 (current known version).
  If schemaVersion is missing:
    Treat as version "1.0" (pre-versioning legacy). Print a note and continue.
  If MAJOR version matches (1.x) and MINOR ≤ 3:
    Proceed normally.
  If MAJOR version matches but MINOR > 3:
    Print: "⚠ stack-profile.json schemaVersion {version} is newer than expected (≤ 1.3). Proceeding — unrecognized fields will be ignored."
    Continue with warning.
  If MAJOR version differs:
    Print: "Error: stack-profile.json schemaVersion {version} has an incompatible MAJOR version. Expected 1.x."
    Print: "Update bestest to the latest version, or re-run /bestest init to regenerate."
    Exit.

Validate scan-report.json schemaVersion (if loaded):
  Expected version: ≤ 1.2 (current known version).
  If schemaVersion is missing:
    Treat as version "1.0" (pre-versioning legacy). Print a note and continue.
  If MAJOR version matches (1.x) and MINOR ≤ 2:
    Proceed normally.
  If MAJOR version matches but MINOR > 2:
    Print: "⚠ scan-report.json schemaVersion {version} is newer than expected (≤ 1.2). Proceeding — unrecognized fields will be ignored."
    Continue with warning.
  If MAJOR version differs:
    Print: "Error: scan-report.json schemaVersion {version} has an incompatible MAJOR version. Expected 1.x."
    Print: "Update bestest to the latest version, or re-run /bestest scan to regenerate."
    Exit.
```

## Shared Test Helpers (Phase 2 Step 6 Full Detail)

```
If existing *_test.go files or testutil/ packages exist:
  Read them to discover shared test helpers, mock implementations, and fake implementations.
  Categorize helpers by purpose:
    - Fake implementations (FakeUserStore, MockHTTPClient) → reuse in generated tests
    - Test data builders (newUser, newItem) → reuse for test data construction
    - Setup helpers (setupTestDB, setupTestServer) → reuse for test environment
    - Assertion helpers (assertUserEqual) → reuse for test verification
  If a suitable helper already exists, reference it instead of creating a new one.
  If no suitable helper exists, generate self-contained helpers in the test file.

Check for testdata/ directories:
  If testdata/ exists, check for golden files and fixture data.
  Generated tests may reference testdata/ fixtures when appropriate (e.g., JSON test fixtures).
```
